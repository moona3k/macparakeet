# 0.8.5 release postmortem

Date: 2026-09-17. After-action on cutting MacParakeet 0.8.5 (Sparkle + GitHub +
website). Written from live notarization history, GitHub/R2/appcast checks, CI
runs, and the release worktree logs — not from memory.

Related: [#1079](https://github.com/moona3k/macparakeet/issues/1079),
[#1082](https://github.com/moona3k/macparakeet/pull/1082),
[#1083](https://github.com/moona3k/macparakeet/pull/1083), website
[#73](https://github.com/moona3k/macparakeet-website/pull/73),
investigation [`2026-09-17-issue-1079-wrapping-up.md`](./2026-09-17-issue-1079-wrapping-up.md).
Canonical procedure: [`docs/distribution.md`](../distribution.md).

## Verdict

**The 0.8.5 public artifacts are consistent.** Tag `v0.8.5` points at
`fb186349` (the #1079 fix). Appcast, R2, and the GitHub Homebrew asset are the
same 174,140,520-byte DMG. Sparkle notes correctly call Wrapping up a
**cosmetic status label**. In-app Check for Updates and Homebrew autobump were
not exercised; the demo smoke failed on a millisecond `say` fixture, which is
not a 0.8.5 capture regression.

The release still burned about **two hours of agent time** on two operational
traps that the then-current docs treated as “wait it out”:

1. Default `notarytool submit` on this Mac SIGBUS-crashes (exit 138) and
   registers **ghost** `In Progress` IDs whose uploads never finished.
2. Local `gh release upload` of the ~174 MB DMG fails TLS against
   `uploads.github.com`. GitHub-hosted `gh` also hung. Ubuntu `curl` of the
   already-verified R2 object attached the asset in 29 seconds.

Both traps are now recorded as gotchas, and `scripts/dist/sign_notarize.sh`
submits with the flags that actually completed today.

## What went well

- Worktree from `origin/main`, not the dirty primary checkout.
- Tagged the **code** SHA (`fb186349`), then recorded the release in a follow-up docs PR. Sparkle users do not need the spec bump inside the DMG.
- Did not rebuild after the notarization crash. The signed app and zip were reused. Bytes that later Accepted are the bytes that shipped.
- Size, SHA-256, Sparkle `length`, R2 `content-length`, and GitHub asset digest were compared, not assumed from “upload started”.
- Release notes stayed honest: Wrapping up was UI-only. Capture and transcription were not stuck. Also-in-this-build items from 0.8.4 were written so skip-version Sparkle users still see them (Sparkle 2 shows only the newest `<description>`).
- CLI stayed 4.3.0. Unreleased changelog was empty; no fake CLI bump.
- Echo-suppression assets were reused; `REQUIRE_MEETING_ECHO_ASSETS=1` bundle checks passed.
- Full-suite owner was CI on the merge commit, not a second local `swift test` of 4,300+ tests.
- `gh pr merge` from a worktree can fail locally when `main` is checked out elsewhere; remote merge of #1082 / website 73 / #1083 still succeeded. Verify with `gh pr view`, not the local checkout.

## What went badly

### 1. Polled ghost notarization IDs because the docs said to

`docs/distribution.md` gotcha 1 / 1a (as of 0.8.5 ship) said:

- a local crash is not proof that no submission exists (true)
- find the ID in `notarytool history` and poll it (true for a **finished** upload)
- do not resubmit solely because Apple is slow (true for a **finished** upload)

The 0.8.5 agent followed that literally. Default `notarytool submit` (progress +
S3 acceleration, no `--wait`) still SIGBUS-crashes on this Mac. Apple then
lists an ID whose status stays `In Progress` indefinitely because the file
never finished uploading. Polling that ID cannot converge.

Same-day evidence, 0.8.4 morning: seven `MacParakeet.dmg` IDs `In Progress`
between 05:50Z and 06:17Z, then one `Accepted` at 06:20Z
(`0073733f-93d8-4dbe-b733-dca6b8cb1d60`). The 0.8.0 packaging note
(`docs/qa/2026-09-07-0.8.0/packaging-sparkle-finding.md`) already saw SIGBUS
138 with a registered ID still `In Progress` eleven minutes later.

The user instruction was the right recovery: **after an error, start fresh**.
Resubmit the **same bytes** with:

```bash
xcrun notarytool submit dist/MacParakeet.app.zip \
  --keychain-profile "AC_PASSWORD" \
  --no-wait --no-progress --no-s3-acceleration \
  --output-format json
```

That path printed `Successfully uploaded file` and Accepted in under a minute.
Do not rebuild. Do not keep polling crash-era IDs.

### 2. Tried to push 174 MB to GitHub from this Mac

R2 upload from the same machine worked. GitHub `uploads.github.com` did not:

- `gh release create` / `gh release upload` → HTTP 500, `tls: bad record MAC`
- macOS LibreSSL `curl` stalled around 11% (~18.5 MB)
- OpenSSL `curl` reached ~83% then 500
- `gh release upload` **from GitHub Actions** hung 18 minutes with no asset

The working attach is Linux `curl` of the **already-published R2 object**, after
size and SHA-256 match the local `dist/MacParakeet.dmg`, POST to the GitHub
releases upload API as `MacParakeet.dmg`. Create the GitHub release **without**
the asset first so a failed upload does not leave a missing tag.

### 3. False alarms and skipped cosmetics

- `scripts/dev/release_demo_smoke.sh` failed: isolated DB, CLI 4.3.0 present,
  synthesized `say` fixture produced an empty transcript (reported duration on
  the order of milliseconds). That is a fixture/ASR smoke flake, not a 0.8.5
  capture regression. Do not block a UI-label patch on it. Health and
  `yt-dlp --version` passed.
- Finder DMG icon layout was skipped (`timeout` is not on stock macOS;
  `osascript` then returned non-zero). The Applications symlink was still
  created. Cosmetic; do not relitigate the DMG.
- A fresh-worktree `swift test --filter CLIVersionTests` compiled the world and
  was killed. Skip that when Unreleased is empty and CI on the tag SHA is green.
- In-app **Check for Updates…** was not exercised. Public appcast/R2/GitHub
  identity was. Say so in the handoff.

### 4. Process friction that did not change the bits

- Primary `macparakeet` checkout was dirty and behind `origin/main`. Website
  `main` was tens of commits behind. Release work stayed in worktrees; that
  was correct.
- First GitHub release attempt combined tag creation with the DMG upload, so
  a TLS failure also delayed having a public tag. Split them.
- The one-shot `chore/upload-0.8.5-dmg` branch was deleted after the asset
  landed. Do not leave a permanent upload workflow on `main` unless someone
  asks for one. The recipe lives in `docs/distribution.md`.

## Self-reflection (release agent)

I treated “Apple registered an ID” as “the upload finished.” History listing
an `In Progress` row is a **reservation**, not a receipt. The receipt is
`Successfully uploaded file` (JSON) followed by `Accepted`.

I also treated gotcha 1a (“do not resubmit because slow”) as a ban on
resubmitting after a **crash**. The user had already seen this: hung
submissions after errors stay hung. The 0.8.4 morning history sitting in the
same keychain would have been enough to skip the 30-minute poll.

I spent longer on local GitHub uploads than on the working R2 path. Once R2
matched, GitHub should have been “attach those bytes from Linux,” not “retry
LibreSSL.” Using `gh release upload` inside Actions repeated the same client
in a different place; raw `curl` was the fix.

I over-verified CLI version tests and under-verified the in-app Sparkle menu.
The public feed identity is the release gate. Sparkle UI is still worth a
manual click when a human is at the Mac.

## Lessons for future agents

Promote these; do not copy this timeline into `AGENTS.md`.

1. **Submit notarization with `--no-wait --no-progress --no-s3-acceleration --output-format json`.** Never `--wait`. If the process exits 138 / SIGBUS, the history ID is a ghost. Resubmit the same artifact with those flags. Poll only IDs that printed `Successfully uploaded file`.
2. **Preserve `dist/`.** Crash ≠ rebuild. Staple only the artifact whose submission is `Accepted`.
3. **Publish R2 first, GitHub second.** Create `vX.Y.Z` without assets. Attach `MacParakeet.dmg` from a GitHub-hosted Ubuntu job that downloads the verified R2 object and POSTs it. Local 174 MB uploads to GitHub from this Mac are not reliable.
4. **Identity is size + SHA-256 + Sparkle length + R2 content-length + GitHub digest.** Matching any one of them is not enough.
5. **Empty `say`-fixture smoke is not a product regression** for a UI-status patch. Isolated DB, millisecond WAV, empty transcript → inspect the fixture, do not reopen capture.
6. **`timeout(1)` is not on stock macOS.** Finder layout may skip; Applications symlink must not.
7. **Full suite has one owner.** CI on the tag SHA is enough when the patch is already covered by focused tests.
8. **Worktrees from `origin/main`.** Dirty local `main` is not a release checkout. `gh pr merge` failing locally does not mean GitHub failed.
9. **After an error, start fresh** on the failed *transport* (notarization upload, GitHub upload). Do not start fresh on the *bytes* if they already signed cleanly.
