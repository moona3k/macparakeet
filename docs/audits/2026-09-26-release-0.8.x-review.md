# Release 0.8.x review

Date: 2026-09-26. Published baseline: `v0.8.7`. Reviewed main:
`81f10c464237a3cfb95314e542e27fb4f09baec0`.

## Verdict

Hold release for the analysis-route and unsaved-result-draft defects below.
GUI/CLI parity is incomplete, and several active specs need correction. Promote
the pending CLI changes before packaging. The requested app release remains
0.8.x; this audit does not authorize publication or change that version choice.

The user reports visual QA passed. Findings here come from source and contract
review; the new GUI failure scenarios were not reproduced interactively.
No application source, existing document, user data, or other session's checkout
was modified. This report is local and uncommitted.

## Functional findings

### P1: Manual prompt results override the analysis model with the default model

Trigger: configure different Default AI and Meetings & library models, then run
a GUI prompt without an explicit per-prompt model override.

`PromptResultsViewModel.refreshModelInfo` reads `loadConfig()` at line 301 and
sets the default model at line 319. `resolvedModelSnapshot` (1052–1061) returns
that model; enqueue captures it at 786 and generation forwards it as
`modelOverride` at 838–842. `LLMService` (1118–1119) resolves the analysis route
and then overlays this default model name.

Same-provider routes silently use the wrong model. Different-provider routes
can reject the incompatible identifier; an Apple Intelligence analysis route
rejects a different default model deterministically. This violates ADR-032 and
diverges from callers that let the shared service resolve analysis normally.
Asynchronous discovery does not repair this: it updates available choices, not
the captured current model.

Fix the implicit model snapshot, provider information and model discovery to
use the resolved analysis route. Preserve intentional per-prompt overrides.
Test the view model through the real LLMService with a capturing fake client:
different models on one provider, different providers, Apple Intelligence,
and explicit per-prompt override precedence.

### P2: Analysis model pickers change the wrong saved route

`TranscriptChatViewModel` reads the default config at 119 and updates its model
at 145. Chat generation at 288 uses the analysis route without a model override.
With an analysis override, the picker therefore shows the wrong configuration
and changing it does not change the chat model. It changes the default used by
Transforms and any inheriting cleanup route instead. PromptResultsViewModel's
picker has the same default-only read/write behavior at 301–327.

Read and update the active analysis override when present, and the default when
analysis inherits. Test that unrelated default settings remain unchanged.

### P2: Editing a second saved result silently loses the first draft

Edit result A, enter unsaved text, switch to result B and click Edit.
`TranscriptResultView.selectTab` (3169–3177) gates only Notes navigation.
B's Edit action (3389–3403) calls `beginEditingPromptResult` directly.
`canEditPromptResult` (518–520) checks existence and regeneration, but not
another dirty draft. `beginEditingPromptResult` (527–531) replaces the sole
editing ID and draft. A's changes disappear without Save or explicit discard.

Guard replacement of a dirty edit session at the view-model boundary. Require
Save or explicit discard, or retain separate drafts. Add a regression test for
the A-to-B sequence and verify returning to A preserves its draft.

## GUI/CLI parity

| Surface | Assessment |
| --- | --- |
| Saved AI-result edits | Gap: GUI conditionally updates the existing result and preserves provenance; `meetings results` exposes only list/add (MeetingsCommand 841–849). Reading `contentEditedAt` is supported, mutation is not. |
| Reading-view omission and batch edits | Gap: GUI uses one reversible `reviseText` command; CLI corrections (MeetingsCommand 208–221) has no omit/batch equivalent. Empty edit-line text is rejected at 1658–1670; sequential commands do not preserve the single Undo boundary. |
| AI task-route configuration | Gap: GUI configures cleanup/analysis overrides; public CLI cannot inspect or configure those saved overrides. Shared execution can honor them. Default LLM configuration was already GUI-owned; this is an additive parity gap. |
| Orukeet, Apple Intelligence inline use, language policy, spoken punctuation, capture sounds, Escape setting, vocabulary replace-all, failed-dictation retry | Corresponding CLI additions inspected. No removed commands, flags or JSON fields found in this review. |
| Inline provider commands | Intentionally independent configurations under ADR-032; they need not inherit GUI settings. |
| Experimental Voice Control | GUI release gate remains false; startup does not create its coordinator/adapter/hotkey in release builds. Offline CLI replay remains exposed by design; `--jev` explicitly requests network-backed diagnostics. |

For complete parity, expose conditional saved-result editing and revision-checked
batch corrections through the existing shared services, and add task-route
inspection/configuration. Otherwise document explicit deferrals and avoid a
claim of full GUI/CLI parity. These gaps are distinct from the functional bugs.

## Documentation and release preparation

- `spec/02-features.md:1516–1523` still describes Community-1 as the sole
  pipeline, FluidAudio 0.15.7, a roughly 130 MB download and exclusive overlap
  trimming. Current automatic detection uses Nemotron on 0.17.4; explicit
  constraints/voice profiles retain Community-1. Both caches are prepared,
  and Nemotron activity can overlap. ADR-010 and spec/06's diarization section
  already describe the newer behavior.
- `spec/03-architecture.md:319` still pins FluidAudio 0.15.7, contradicting
  Package.swift and Package.resolved (0.17.4).
- `spec/06-stt-engine.md:58` says native Nemotron streamed final text is the
  dictation result and the WAV is a fallback. DictationService now cancels/drains
  live preview and uses recorded-file transcription for the authoritative result
  (653–657 and 1858). The STT subsystem README is already aligned.
- `docs/audits/2026-09-24-final-0.9.0-readiness.md:18–20` recommends 0.9.0 over
  0.8.8. It is a dated audit, but needs a supersession note so it does not steer
  release work against the current 0.8.x request. The generic version guidance
  in distribution.md should record the deliberate release-train exception.
- CLI CHANGELOG has nonempty Unreleased entries (failed dictation history/retry
  and new diarization behavior), while CLI.cliVersion remains 4.6.0. Follow
  distribution.md:240–248: choose the CLI semver under its compatibility policy,
  promote the entries, and update the embedded CLI before packaging. Existing
  CLIVersionTests only compare against the latest released header; they do not
  reject nonempty Unreleased entries.
