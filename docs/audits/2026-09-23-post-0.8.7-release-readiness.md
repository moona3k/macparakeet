Two prompt-result defects on this head need a follow-up before the stable cut:

1. Retranscription can reset the correction revision to zero while changing
   transcript text, making an old summary look current. The review branch adds
   a persisted hash of timed cue words when available, otherwise trimmed
   automatic clean/raw source text, to new results and
   compares it when rendering the Update affordance. Legacy results retain an
   unknown receipt and are offered Update; assigning them today's transcript
   hash would falsely certify results already stale before migration.
2. A failed summary regeneration can be retried after the user edits and saves
   the original result. An unconditional replacement then deletes that edit.
   The review branch snapshots the original content/edit timestamp and checks
   them in the replacement transaction. A changed original remains saved and
   the retry fails visibly.

The fixes are in [PR #1127](https://github.com/moona3k/macparakeet/pull/1127),
with a [review walkthrough](https://macparakeet.com/dev/pr/1127/). Focused tests
cover retry after a saved edit, an edit during generation, transactional
mismatch and success, source freshness, migration, CLI result receipts, and
saved-audio completion. One full local `swift test` passed 7,411 XCTest cases
with 27 skipped and zero failures; Swift Testing's 30 tests in three suites
also passed. The first hosted run found a startup-order race in a meeting
capture test: a synthetic system buffer could satisfy readiness before the
mock microphone installed the callback that test immediately inspected. Its
fixture now requires microphone readiness; the affected 37 tests passed under
parallel execution. Final review also found that an empty unedited clean text
field could produce an empty source receipt despite raw or cue input. The
receipt now follows cue text when present and otherwise uses clean/raw source
text, with model and CLI command tests. Exact-head hosted CI and review are
separate merge gates. The host is macOS 26.6.2, so macOS 27 Instant Dictation
remains unqualified. The 0.8.7 field report
[#1115](https://github.com/moona3k/macparakeet/issues/1115) still lacks
diagnostics for its preview-works/stop-rejects symptom; the independent
stop-time audio-health check is a plausible path, not a confirmed cause.
Long-transcript editing, signed DMG capture, meeting recording, and Sparkle
upgrade also remain physical release gates.

## Verdict

**Hold the next stable release.** The reviewed `main` passed CI, including release build, bundle smoke, Swift 6 checks, and the full Swift test suite ([run 35835133400](https://github.com/moona3k/macparakeet/actions/runs/35835133400)). Three additional defects found in this review have focused fixes in `review/release-readiness-2026-09-23`. Two pre-existing, user-facing follow-up fixes were prepared in [PR #1122](https://github.com/moona3k/macparakeet/pull/1122) and [PR #1123](https://github.com/moona3k/macparakeet/pull/1123); neither was in the reviewed `main` commit, and both have since merged. Summary freshness across retranscription remains unresolved. The macOS 27 Instant Dictation fix has synthetic coverage but still needs the on-device qualification called for by its [root-cause audit](2026-09-19-issue-1102-instant-dictation-mic-reacquire-loop.md).

## What the review covered

- Capture: microphone engine changes, dictation lifecycle and hotkeys, overlays, capture cues, and restart races.
- Local artifacts: transcription editing, correction migration and revision receipts, prompt results, vocabulary replacement, meeting AI language, Orukeet cache and model selection, and CLI persistence contracts.
- UI and integration: menu-bar Transforms, interaction arbitration, release feature gates, build/package changes, and current CI.
- Experimental Voice Control: authority, AX and OCR observations, pixel actions, speech sessions, privacy boundaries, and its release gate. It is disabled in release builds (`AppFeatures.voiceControlEnabled = false`).

The reviewers traced changed paths and adjacent tests in each area. The 31,000-line delta is too large for an exhaustive line-by-line or real-device claim. No broad refactor is justified by the concrete findings: the vocabulary replace-all transaction, populated correction migration fixture, and staged Orukeet cache replacement have clear ownership and focused coverage. Orukeet's actual pinned archive and runtime loading remain opt-in tests. The maintainability pass found that `MenuBarCoordinator` and `PromptResultsViewModel` now exceed 1,000 lines; neither file size alone nor the reviewed paths showed a release regression that warrants a late structural split.

## Fixes prepared on the review branch

| Finding | Trigger and effect | Correction |
| --- | --- | --- |
| CLI prompt result loses its input correction revision | `prompts run` on an edited meeting uses corrected text but saves a nil receipt; the app immediately offers Update for the new result. | Persist the revision from the same attribution projection that supplied the input text. |
| Saved-audio auto-prompt result can look fresh after a concurrent edit | The service snapshots text, awaits card/LLM work, then reads a newer correction revision. | Capture text and revision together before provider work. A barrier test edits during generation and asserts the original text and revision remain paired. |
| Refused dictation hotkey leaves its gesture active | A Transform/history paste owns GUI mutation; the hotkey manager enters recording mode before the flow rejects Start. The next press stops the phantom take. | Return explicit start acceptance, reset the refused gesture, and acquire no lasting lease for a rejected flow transition. |

The package manifest also excludes the new Voice Control README from SwiftPM's source target, removing an unhandled-file build warning. The hotkey cleanup unifies duplicate clipboard/AI-polish collision code. A later review retained the unused `SettingsDictationHotkeyConflictPolicy` wrapper because it is public in the `MacParakeetCore` library and its removal is unnecessary for these fixes.

Focused verification: `PromptsCommandTests` and `SavedAudioAutoPromptCompletionServiceTests` passed (98 selected tests including matching neighboring suites); `AppHotkeyCoordinatorTests` and `DictationFlowCoordinatorTests` passed (67 tests). The added concurrent-edit assertion also passed independently. A single full local `swift test` passed 7,395 tests with 27 skipped and zero failures after the behavior fixes, before the original cleanups and manifest warning exclusion. The final original cleanups passed 60 focused tests, and the final `swift build` passed without warnings. ## Release findings and boundaries

1. **Rapid dictation restart:** [issue #1120](https://github.com/moona3k/macparakeet/issues/1120) describes a stale cancel that can change the state of a live replacement take. [PR #1122](https://github.com/moona3k/macparakeet/pull/1122) has since merged; combined-main CI passed. Physical rapid-restart capture was not repeated here.
2. **Reading-view editing:** [issue #1119](https://github.com/moona3k/macparakeet/issues/1119) covers a save result appearing on another transcript, edits made during save being dropped, and a retry losing its correction revision. [PR #1123](https://github.com/moona3k/macparakeet/pull/1123) has since merged; combined-main CI passed. Long-transcript GUI use remains unverified.
3. **Retranscription freshness:** Prompt results survive retranscription, but `PromptResultFreshness` compares only correction revisions. The new transcript resets that revision to zero; an old revision-zero result can appear current even when its source text changed. Resolve this with durable source identity or an explicit invalidation receipt before treating the new Update affordance as reliable. Avoid inferring freshness from `Transcription.updatedAt`, which also changes for metadata.
4. **macOS 27 Instant Dictation:** the merged microphone re-acquisition fix is source- and simulation-verified. This host is macOS 26.6.2; the [audit](2026-09-19-issue-1102-instant-dictation-mic-reacquire-loop.md) calls for on-device macOS 27 validation of the self-emitted configuration change and real capture.
5. **Signed-app qualification:** no new signed DMG, Sparkle upgrade, physical microphone/meeting, or long-transcript UI run was performed for this candidate. The current stable app was running during this review, so a second global-hotkey dev instance was not launched. These are separate from build and unit-test success.

Voice Control stays off for this release candidate. Before enabling it, fix the stale AX text fallback, make the Screen Text opt-out effective without relaunch, suppress OCR when secure-field coverage is incomplete, revalidate OCR pixel targets and their consequences at execution, and require silence after an overlong hands-free utterance. The native/browser, microphone, and real-app qualification in [ADR-033](../../spec/adr/033-explicit-voice-control.md) also remains open. Its default-off status keeps these experimental paths out of the stable app runtime; it does not make them ready to enable.

Open field reports such as [#1115](https://github.com/moona3k/macparakeet/issues/1115) (preview works, stop reports microphone unavailable on 0.8.7) and [#931](https://github.com/moona3k/macparakeet/issues/931) (intermittent missing meeting audio on 0.7.3) still need diagnostics or physical reproduction. They are release risk signals, not proof that this candidate regressed those paths.
