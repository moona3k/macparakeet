# v0.8.0 crash evidence and follow-up audit — 2026-09-12

The investigation found a confirmed native packaging mismatch and several concrete crash-path hazards. It did not establish one cause for every reported crash. The changes address the evidenced packaging, window-lifecycle and diagnostic weaknesses while preserving the remaining uncertainty around LocalVQE, shared Core ML inference and unidentified clusters.

## Findings and their limits

| Area | Confirmed evidence or defect | What remains unproven |
|---|---|---|
| Native packaging | LocalVQE declares minimum macOS 26.0 while the app promises 14.2. Preparation omitted an explicit target; the cache stamp and bundle verifier did not enforce it. | This incompatibility is not proof that it caused every LocalVQE-related incident or the observed native leaf fault. |
| Window close, cluster E | Released app PCs symbolicate to `AppWindowCoordinator.windowWillClose`. Synchronous hosting-view destruction during the close callback is an actionable lifecycle hazard. Teardown is now deferred after detaching ownership. | An optimized thunk label does not establish that `windowDidBecomeMain` called `windowWillClose`, or prove every incident is cured. |
| ScreenCaptureKit stop error, cluster B | Released frames include `TelemetryErrorClassifier.classify` and `SystemAudioStream.didStopWithError`. Snapshotting numeric/domain information removes reflection, localization and free-form error logging from this callback. | Access to the supplied error still occurs. This cannot repair a dangling NSError and is hardening rather than a demonstrated incident cure. |
| LocalVQE, cluster C | App symbolication reaches `DynamicLibraryMeetingEchoProcessor.processFrame`. A proposed native mapping produces a coherent LocalVQE/ggml chain. | The dylib UUID/load address is missing. The inferred load address and native leaf attribution remain conditional; no GGML allocation assertion or global-concurrency cause is established. |
| TDT, cluster D | Released frames reach `TdtDecoderV3`. The released FluidAudio source is v0.15.4; current main uses v0.15.6, which still contains shared-model cloning and synchronous decoder/joint inference. | Shared-model synchronous prediction is a credible concurrency concern, not a proven explanation for every hardware/OS-specific crash. |
| Clusters A and F/G/H/I | Existing reports lack enough attributable evidence for a defensible source fix. | Shared frame positions, particularly the frame following a signal handler, do not establish a common Core ML leaf or another common cause. |

A caller frame is not necessarily the faulting instruction. The first frame after the handler may be the signal trampoline. This is why the diagnostic change records the interrupted PC directly from `SA_SIGINFO`/`ucontext`, together with `si_code` and fault address.

## Native compatibility and the existing Sonoma fix

The packaging fix explicitly passes the native deployment target through preparation, includes it in cache identity and verifies the minimum OS of each bundled Mach-O architecture slice against the app declaration. This prevents a build on a newer host from silently shipping an incompatible native artifact. Rechecking source confirmed the new cache field and per-slice verifier in `scripts/dist/`.

We rebuilt the pinned native source for 14.2 and observed a matching load command. On the current Apple Silicon host it processed 100 synthetic microphone/reference frames at 16 kHz with hop 256, finite output and successful return codes. That is evidence of build configuration and current-host execution, not a macOS 14/15 compatibility run.

PR #998 already limits Parakeet TDT inner chunk concurrency to one on macOS 14. macOS 15+ retains the default concurrency of four, and dictation is unchanged. Do not duplicate this existing fix or treat current-main behavior as shipped v0.8.0 behavior. Broadly serializing all model inference could delay interactive dictation behind long background work and needs its own measured decision. A native abort, trap or segmentation fault cannot be converted into a Swift thrown error by wrapping asynchronous transcription in an Objective-C exception handler.

## Signal-path implementation lessons

The minimum report must be independent of unsafe unwinding. The first C implementation still called `snprintf` before the first write; bounded output alone does not make a formatter async-signal-safe. The revised path uses fixed buffers, byte copies and integer arithmetic. It handles the full signed 32-bit `si_code` range without signed-negation overflow and obtains the interrupted PC from architecture-specific machine context.

Writes retry after EINTR and advance after short writes. A zero result or another error stops the attempt; optional backtrace capture is skipped unless the complete minimum report was accepted by `write`. Best-effort `backtrace()` remains explicitly unsafe and can allocate, deadlock or crash. It does not belong before minimum evidence. Successful writes are not a power-loss durability guarantee, and a concurrent fatal signal can terminate the first writer before completion. Competing crash handlers do not sleep or spin waiting for each other, and no path attempts recovery.

The alternate signal stack now has stable C storage for the process lifetime rather than an escaped Swift array pointer. Registration remains main-thread-only; worker-thread stack-overflow reporting is consequently limited. The richer Objective-C exception path claims the shared guard only after its report write succeeds, allowing the signal fallback when that write fails.

The report parser admits the new fields only for signal reports. `si_code` requires at most ten ASCII digits, an optional minus sign and a valid Int32 value. PC/fault addresses require bounded ASCII hexadecimal. Unicode lookalikes, malformed values and oversized values are dropped rather than forwarded. Old reports still parse without these optional fields. A fullwidth hexadecimal regression test protects this distinction.

### SIGTRAP regression and termination

The initial production-linked six-signal probe observed SIGTRAP terminating as SIGILL (`-4`) instead of SIGTRAP (`-5`). Relying on `SA_RESETHAND` was insufficient for this case on Darwin. Every fatal exit now calls one nonreturning helper that explicitly restores `SIG_DFL`, raises the original signal and calls `_exit` if raising unexpectedly returns. Minimum-report ownership and ordering are unchanged.

The fixed production-linked probe was rerun independently. All six exit dispositions and report signal values match:

| Trigger | Process return code | Report signal |
|---|---:|---:|
| SIGSEGV | -11 | 11 |
| SIGABRT | -6 | 6 |
| SIGBUS | -10 | 10 |
| SIGILL | -4 | 4 |
| SIGTRAP | -5 | 5 |
| SIGFPE | -8 | 8 |

The persistent regression is `testEveryInstalledSignalExitsViaItsOwnDefaultDisposition` in `CrashReporterSignalProbeTests.swift`. The harness contains explicit `raise_*` modes and links the unchanged production handler source into the probe executable. The real null-store probe separately checks that the PC lies in the interrupted function, not the handler.

## Verification and remaining work — pending final gate

Nine additional standalone probe cases passed: ordinary abort, real null-store fault, reinstall, long metadata, short writes, EINTR followed by short writes, zero writes, empty backtrace and abrupt exit from backtrace. Abrupt exit proves minimum evidence existed before backtrace began; a stub returning zero alone would not establish that ordering. Zero-write mode also makes backtrace exit abruptly if called, proving the unsafe step is skipped after minimum-write failure.

Harness-side symbol overrides inject failures without production test flags. Loader symbols are resolved before signal handling. A child-owned alarm bounds a hung probe; unexpected SIGALRM fails the expected termination assertion without a delayed parent callback targeting a reused PID. Compiler and `nm` pipes are drained before waiting to avoid full-pipe deadlock. A separate direct formatter check passed Int32 minimum/maximum, Int64 minimum, UInt64 maximum and a buffer-boundary sentinel. C probes compiled with `-std=c11 -Wall -Wextra -Werror`; diff checks passed.

At drafting handoff, the host reports that findings from eight independent Sonnet review lenses and an actual Fable review are resolved in combined runtime commit `72731fdd`. The focused Swift build is in progress. Local Greptile review is unavailable because its client is not signed in; it must not be represented as a passed check. The final publishing gate remains pending.

The standalone results do not replace final Swift compilation/tests, release-artifact verification or physical macOS 14/15 testing. An intermediate parser edit had an extra closing parenthesis and was corrected; a host-observed missing imported C symbol was traced to a stale task-local Clang module cache, while a cold import probe passed. Neither issue justifies a public C export workaround. Final Swift validation is pending and will be recorded in the PR before readiness is claimed.

LocalVQE native fault causality, the conditional native symbol mapping, TDT shared-model concurrency and unidentified clusters remain open. Per-instance locking does not establish cross-instance safety or unsafety. Helper-process isolation would be a separate containment architecture change; neither isolation nor disabling the feature follows automatically from the deployment-target fix. Better signal context improves the next investigation but cannot reconstruct information absent from old reports.

Sonnet and Fable second opinions informed the work; their hypotheses were checked against source and runtime evidence. Suggested concurrent-handler sleeps, deleting malformed user reports and recovering from fatal signals were rejected. The signal-review snapshots supplied for this follow-up contained source, tests and contracts, not user audio or transcripts. This document contains no raw telemetry identifiers.

## Reproducing and extending the investigation

The committed `CrashReporterSignalProbeTests` compiles `scripts/dev/tests/crash_signal_probe_harness.c` with the production handler and verifies behavior in disposable children. Run `swift test --filter CrashReporterSignalProbeTests`; parser and upload compatibility live in `CrashReporterTests`. Native distribution fixtures are in `scripts/dist/tests/` and run in CI. Temporary local review logs are supporting evidence, not a substitute for those persistent checks.

For a new crash cohort, query Cloudflare D1 `events` read-only for `event='crash_occurred'`, filter by the **crashed** app version, and retain the incident/upload distinction. Verify the release asset hash and dSYM UUID before symbolication. Record the exact native UUID/load address when available; the candidate C mapping in this cohort assumes load address `0x128000000` and reaches `ggml_init+28`, immediately after the mutex-lock call. That assumption remains conditional.

After the next release, compare reports by crashed app version, OS, signal and interrupted PC. Exercise close/reopen during capture and echo-enabled meetings on macOS 14 and 15. A reduction in one cluster does not validate unrelated clusters, and successful current-host synthetic audio does not establish older-OS compatibility.
