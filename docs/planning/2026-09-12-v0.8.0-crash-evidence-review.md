# v0.8.0 crash review — 2026-09-12

Follow-up to the September 11 v0.8.0 crash investigation, checked against Cloudflare D1 and the exact released binary. Live D1 read at approximately 17:20Z returned the same 24 attributed signal rows, latest upload 2026-09-12T16:08:52Z; no database writes. Upload time is not incident time; post-launch events are not the crashed process.

## Corrections to the original analysis

1. A named caller is not proof of the faulting instruction. Frame1 after the handler is likely the signal trampoline. In particular A/B sharing frame1 is not evidence they share a CoreML leaf. The reporter needs interrupted PC from SA_SIGINFO/ucontext.
2. The E thunk label does not establish that windowDidBecomeMain invoked windowWillClose; optimized thunk attribution can be misleading. The actionable hazard is synchronous destruction of the hosting view during close notification.
3. B snapshotting domain/code removes reflection, localization and free-form logging, but still must access the supplied error. It does not repair a dangling NSError and is hardening, not a proven incident cure.
4. C presumed dylib load0x128000000 produces a coherent chain through localvqe_process_frame_f32 -> stream_one_frame -> process_frame_graph -> CPU ggml -> ggml_init+28, immediately after ggml_critical_section_start (mutex lock). The report lacks the dylib UUID/load address, so this mapping remains conditional. Do not assert a GGML allocation assertion or global concurrency cause from this alone.
5. Native abort/trap/segfault cannot be converted to a Swift thrown error by an NSException wrapper around async transcribe. No such wrapper is an acceptable fix for D.
6. FluidAudio shipped source is v0.15.4; current main pins v0.15.6. Current pin alone must not be used to relabel the release. The shared-model clone and synchronous decoder/joint inference path remain in v0.15.6.

## Scope and remaining uncertainty

The resulting changes pin and verify the native deployment target, defer window hosting-view teardown, restrict SCKit stop-error inspection, and write interrupted signal context before best-effort unwinding. Do not rewrite unidentified UI paths or broadly serialize all model inference without investigating dictation responsiveness.

LocalVQE native fault cause is unresolved. Per-instance locking alone neither proves cross-instance unsafety nor guarantees safety; helper isolation is a distinct architectural containment change. No helper isolation or disablement is implied by the packaging fix.

TDT synchronous prediction on shared MLModel instances is a credible concurrency defect requiring a vendor/per-model solution. Apple WWDC23 "Improve Core ML integration with async prediction" distinguishes thread-safe async predictions from synchronous calls that callers must serialize (https://developer.apple.com/videos/play/wwdc2023/10049/). Disabling all concurrency may delay interactive dictation behind long background work and is not a validated cure for these incidents. The hardware/OS-specific failures and unsigned F/G/H/I clusters remain unresolved until better reports or reproductions arrive.

Read-only Sonnet and Fable 5.1 second opinions were considered; claims not established by their source access were not promoted to verified causes. Raw telemetry rows and user session identifiers are not copied into this report.
