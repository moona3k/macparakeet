# Anarlog and open-source peers: how they do speaker attribution

Research date: 2026-09-06. Static source review of read-only clones; no app was run, no model downloaded, no script executed.
Anarlog revision: `e4379fb6ec48c1094374054faa97912de6b714a4` (github.com/fastrepl/anarlog, head commit dated 2026-09-07 02:37 +0900). The clone is shallow, so path history comes from the GitHub commits API (observed 2026-09-06, saved under `evidence/peers-anarlog-gh-commits-*.txt`).
Peer revisions: Muesli `4e32a481b729a1e6dd1ac55a334c8fc1971eb1bc`, Meetily `0281737d87d26352fb0adc78c8c0975f691b23d1`, Minutes `fa415a71d196aa0ae863977a4a99eb51d9b6fb6d`, Vibe `4d1db65fd07d7927d7b4ef3a3d949539010147dc`, OpenWhispr `a9cf27b49bdcc9069922641ec39ac06d3483a125`, Handy `bc7facea3a777869182203cfcf5c90f7a98efd99`, VoiceInk `8f089cb4bf2c9c2f217b0cc0af909d9052ff6288`.
MacParakeet comparison: working tree on 2026-09-06 (FluidAudio pinned 0.15.4).

## 1. Verdict

Anarlog does not have a better diarization model than MacParakeet. It has a more complete attribution system around a comparable or older model, and almost all of it landed between 2026-08-11 and 2026-09-05.

- Its bundled local diarizer is a Rust re-implementation of the pyannote 3.1 recipe (segmentation-3.0 plus WeSpeaker ResNet34 embeddings, ONNX Runtime with a CoreML execution provider). MacParakeet's FluidAudio 0.15.4 offline pipeline is pyannote community-1 plus WeSpeaker plus VBx, which is the newer recipe.
- A default local-only Anarlog user gets no speaker separation at all during the live transcript and, in the common case, none afterwards either. The transcript shows "You" for the microphone channel and one unnamed speaker for the system-audio channel. Post-stop diarization runs only when the session lists at least two other participants and the 632 MB Parakeet Batch model has been downloaded.
- What Anarlog does well is everything around the model: channel layout as a speaker prior with in-person detection, the participant count as a clustering bound, on-device voiceprints that both steer clustering and name clusters conservatively, a post-pass that consolidates over-split hosted speakers with the same embedding model, and a correction UI whose every manual assignment feeds the voiceprint store.
- Among the peers, only OpenWhispr and Minutes ship a comparably complete local pipeline (sherpa-onnx or pyannote-rs with segmentation-3.0 and CAM++ embeddings, plus voice profiles). Muesli uses FluidAudio's legacy `DiarizerManager` on system audio only. Vibe uses NVIDIA Sortformer with a hard four-speaker limit. Meetily has no diarization despite marketing it. The dictation apps have none.

The narrow recommendation for MacParakeet is in section 3: keep the FluidAudio community-1 engine, and add Anarlog's priors and post-passes around it rather than swapping the model.

## 2. Findings

### 2.1 Anarlog: STT providers and which return speaker labels

Anarlog routes batch transcription through one `BatchProvider` enum with roughly thirty variants. Only five run on device: whisper.cpp (`WhisperLocal`), Argmax (`Am` on a loopback URL), Soniqo, Apple Speech, and any provider reached through a loopback URL. Everything else is a hosted API. [BatchProvider](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/listener2-core/src/batch/mod.rs#L22-L70), [is_local_batch](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/listener2-core/src/batch/diarize.rs#L46-L61).

Of the local providers, none returns speaker labels from the recognizer itself:

- whisper.cpp and Argmax return words with no speaker. The PR that introduced local diarization states this directly. [PR 7244 body](https://github.com/fastrepl/anarlog/pull/7244)
- Apple Speech (SpeechAnalyzer) emits `speaker: None` on every word. [transcribe-speechanalyzer](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/transcribe-speechanalyzer/src/lib.rs#L234)
- Soniqo is a Swift bridge to the third-party `soniqo/speech-swift` package (exact 0.0.22, Apache-2.0, observed 2026-09-06). Its Parakeet Batch model can run a separate diarization pipeline, but only when the caller supplies an exact speaker count of at least two, and only on channels of at most ten minutes. [Package.swift](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/transcribe-soniqo/swift-lib/Package.swift#L16-L17), [diarize_samples guard](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/transcribe-soniqo/src/lib.rs#L146-L165), [10 minute limit](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/listener2-core/src/batch/simple/local.rs#L815-L825), [per-channel count](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/listener2-core/src/batch/simple/local.rs#L691-L703).

Cloud labels come from the provider (Deepgram, Soniox, AssemblyAI, pyannote.ai `precision-2` for paid Anarlog Cloud). Anarlog ships its own pyannote.ai proxy crates for that tier. [pyannote-cloud](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/pyannote-cloud/src/lib.rs#L1-L4), [api-pyannote routes](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/api-pyannote/src/routes.rs#L1-L30). Local STT is available only on macOS arm64. [platform gate](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/apps/desktop/src/stt/capabilities.ts#L114-L119)

### 2.2 Anarlog: the default local-only speaker path, end to end

This is the path a free user on Apple Silicon with the Soniqo Parakeet Streaming or Apple Speech live model gets.

**During the meeting.** Words carry a channel (0 direct mic, 1 remote party, 2 mixed capture) and no speaker index. The renderer maps the direct-mic channel to "You" whenever the session has an owner, and gives the remote channel one unknown speaker label ("Speaker 1"). If the session has exactly one other participant, that person is assigned to the whole remote channel from the participant list, with no audio analysis. [ChannelProfile](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/transcript/src/types/segment.rs#L5-L20), [label rendering](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/transcript/src/label.rs#L81-L120), [1:1 channel assignment](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/transcript/src/types/speaker.rs#L26-L52). There is no live diarization anywhere in the tree.

**After stop.** The capture lifecycle picks one of three actions. If the live transcript completed and no speaker refinement is wanted, it is "enhance only": no batch pass, no diarization, the channel labels are final. Refinement is wanted only when the session has more than one non-owner participant, and either the provider is paid Anarlog Cloud, or the live model is a realtime local model and the Soniqo Parakeet Batch model is already downloaded. [getPostCaptureAction](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/apps/desktop/src/stt/capture-lifecycle.ts#L136-L158), [refine conditions](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/apps/desktop/src/stt/capture-lifecycle.ts#L221-L235), [download gate](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/apps/desktop/src/stt/useSTTConnection.ts#L56-L59), [realtime local models](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/apps/desktop/src/stt/capabilities.ts#L168-L170). The Parakeet Batch model is a separate 632 MB download. [model sizes](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/transcribe-soniqo/src/model.rs#L132-L140)

**When the batch refine does run.** The desktop re-runs the recording through Soniqo Parakeet Batch with `num_speakers` set to the count of distinct participants including the owner, when that count is above one. [inferred count](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/apps/desktop/src/stt/useRunBatch.ts#L520-L532), [passed to batch](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/apps/desktop/src/stt/useRunBatch.ts#L667-L677). Inside the Rust batch runner, three stages follow in order:

1. Soniqo transcribes each resampled channel file. If the exact count is known and each diarizable channel is under ten minutes, it also runs Soniqo's pyannote community-1 CoreML pipeline with `Community1SpeakerBounds(exact:)` on the system channel with the count minus one, or on a mono file with the full count. Longer recordings skip this stage with a warning. [Soniqo runner](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/listener2-core/src/batch/simple/local.rs#L424-L491), [Swift bridge](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/transcribe-soniqo/swift-lib/src/lib.swift#L845-L865), [community-1 download](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/transcribe-soniqo/swift-lib/src/lib.swift#L196-L212).
2. `apply_local_diarization` runs Anarlog's own `pyannote-local` diarizer on every transcript channel whose words all came back unlabeled, so it is the fallback for Soniqo's skipped cases and the only diarizer for whisper.cpp, Argmax and Apple Speech. [post-process order](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/listener2-core/src/batch/mod.rs#L282-L285), [unlabeled test](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/listener2-core/src/batch/diarize.rs#L231-L238).
3. Voiceprint extraction and naming run in the desktop plugin after the transcript persists (section 2.5).

**The `pyannote-local` diarizer.** The crate header describes it as mirroring pyannote.audio 3.1, tuned for CPU batch use after a recording ends. [pipeline.rs](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/pyannote-local/src/pipeline.rs#L1-L4) The concrete recipe, from source:

- Segmentation: a bundled `segmentation.onnx` (6.0 MB in the tree) run on fixed 10 s windows, decoded as the segmentation-3.0 powerset over three local speakers by argmax. [segmentation.rs](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/pyannote-local/src/segmentation.rs#L6-L28)
- Embeddings: a bundled `embedding.onnx` (26.5 MB), 80 mel bins, 256-dim output, with the waveform scaling and mask threshold copied from pyannote's `ONNXWeSpeakerPretrainedSpeakerEmbedding`. Embeddings are computed per local speaker per window over a sample mask of that speaker's frames; only windows with at least 1.0 s of non-overlapped speech become clustering anchors. [model.rs](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/embedding/src/onnx/model.rs#L1-L8), [config](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/embedding/src/onnx/mod.rs#L12-L26), [anchor rule](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/pyannote-local/src/pipeline.rs#L210-L227).
- Clustering: centroid-linkage agglomerative clustering on unit-normalized embeddings, cut at 0.7045, with clusters backed by fewer than 12 s of anchors absorbed by their nearest large cluster. Speaker bounds from `num/min/max_speakers` override the threshold cut by choosing the merge count whose large-cluster count is closest to the bounds. [defaults](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/pyannote-local/src/pipeline.rs#L45-L62), [cluster](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/pyannote-local/src/clustering.rs#L238-L302).
- Reconstruction: every window votes its local-speaker activity onto a global frame grid under its cluster label; a frame is active for a speaker when votes are at least half the coverage. Window hop is 2 s so each frame sees about five windows. [reconstruct](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/pyannote-local/src/pipeline.rs#L447-L517)
- Word assignment: largest time overlap, falling back to the nearest turn for words in gaps. [assign_words](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/pyannote-local/src/pipeline.rs#L603-L635)
- Compute: the `onnx` crate opts batch models into the CoreML execution provider with the NeuralNetwork format on CPU and Neural Engine, with a comment that this is the only combination that compiles and matches CPU output, at about ten times CPU speed. A corrupt compiled cache is cleared and retried once, then falls back to CPU. [onnx crate](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/onnx/src/lib.rs#L19-L46), [CoreML provider](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/onnx/src/lib.rs#L91-L113).
- Bounded work: `max_windows` 1800 grows the hop on long recordings. Word timings alone cross into the blocking task, so a diarizer failure leaves the transcript intact, and the runner streams progress heartbeats every 5 s so the progressive session's 60 s idle monitor does not kill a long diarization. [max_windows](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/pyannote-local/src/pipeline.rs#L270-L282), [isolation and heartbeat](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/listener2-core/src/batch/diarize.rs#L240-L344).

**Reported numbers (attributed, not reproduced).** PR 7244 reports DER 1.8% on `english_1` and 4.7% on `english_10`, two in-repo fixtures, scored against pyannote.ai `precision-2` output as the reference after correcting a 2.3 s offset, RTF about 0.09 on an x86 CPU; a 5 s hop gave 11.5%. PR 7251 reports DER 4.4% on the same two fixtures with RTF 0.034 on an M5 Max after the CoreML cache repair. The eval binary defaults to a 0.25 s collar; whether overlap was scored is unknown; speaker count was not oracle unless `--exact-speakers` was passed. These are agreement with a commercial system on two clips, not accuracy against human labels, and no AMI or VoxConverse results are committed. [PR 7244](https://github.com/fastrepl/anarlog/pull/7244), [PR 7251](https://github.com/fastrepl/anarlog/pull/7251), [eval binary](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/pyannote-local/src/bin/diarization_eval.rs#L1-L11), [eval loop](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/pyannote-local/eval/PROGRAM.md).

The segmentation code names segmentation-3.0 and the embedding code names WeSpeaker; the user-facing docs list `wespeaker-embedding-onnx-1` for voiceprints. ### 2.3 Anarlog: mic and system channels as a speaker prior

The recording layout is treated as evidence, not thrown away. `plan_channel` maps transcript channels onto recorded audio and a speaker budget:

- Mono recording: score the whole file with the full participant bounds.
- Stereo recording, stereo transcript: never diarize channel 0 (the user alone); diarize channel 1 with every bound shifted down by one because the mic user cannot be on it. A 1:1 call therefore skips diarization entirely.
- Stereo recording downmixed to one transcript channel by whisper or Argmax: score the average of both channel files with the full count, because the direct-mic file alone would miss every remote turn.
- In-person meeting: when the session expected at least two participants but the system-audio channel carried at most 3 s of speech, the mic is treated as shared. Channel 0 is diarized with the full count, and if at least two speakers actually come out, its words are moved to channel 2 (`MixedCapture`) so the renderer stops calling everyone "You". Headphone state is deliberately not a gate. [plan_channel](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/listener2-core/src/batch/diarize.rs#L74-L115), [in_person_capture](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/listener2-core/src/batch/diarize.rs#L117-L134), [shared mic relabel](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/listener2-core/src/batch/diarize.rs#L379-L417), [PR 7285](https://github.com/fastrepl/anarlog/pull/7285).

For hosted providers the same layout drives a different post-pass. `consolidate_hosted_speakers` counts provider labels per channel, derives the expected cap from the participant hints with the same shift, and when labels exceed the cap or known voiceprints exist, embeds each label's clean spans with the same WeSpeaker model and merges labels that match one known person or are most similar, until within cap. It never touches the direct-mic channel of a call. [consolidate.rs](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/listener2-core/src/batch/consolidate.rs#L1-L100), [PR 7280](https://github.com/fastrepl/anarlog/pull/7280).

The live path does the same at the channel level with no audio analysis: `DirectMic` is the "complete" channel by default, and the remote channel becomes complete only for a two-person session. Partial words on a channel inherit the last speaker seen on that channel. [segment options](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/transcript/src/types/speaker.rs#L54-L79), [identity rules](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/transcript/src/segments/speakers.rs#L120-L154).

Two caveats on the "You" assumption. The live path ignores echo: a remote voice leaking into the mic is labeled "You" until the post-stop pass. Section 2.5 shows that the same assumption is used to auto-enroll the owner's voiceprint, gated on headphone output.

### 2.4 Anarlog: timestamps and how speaker labels merge into the transcript

Speaker labels are never written into words. Words live in `transcripts.words_json`; speaker information is a separate overlay in `transcripts.speaker_hints_json`, with three hint types applied in a fixed precedence: `provider_speaker_index` (channel plus index from the diarizer or provider), then `automatic_speaker_assignment` (voiceprint, elimination, or participant-list naming), then `user_speaker_assignment`. [schema](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/db-app/migrations/20260710223922_canonical_data_model.sql#L78-L97), [precedence](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/apps/desktop/src/stt/render-transcript.ts#L221-L241).

Word timestamps are real for whisper.cpp and Argmax batches. They are not real for Soniqo: the Swift bridge returns chunk text plus duration, and the Rust side synthesizes word timings by spreading words uniformly over the chunk, or, when diarization ran, proportionally over the speaker spans that intersect the chunk. Word-level attribution accuracy on the Soniqo path is therefore bounded by chunk and span granularity, not by the recognizer. [synthesized words](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/transcribe-soniqo/src/responses.rs#L170-L296)

When a batch refine replaces a live transcript, the desktop keeps a user's earlier assignments by mapping old speakers to new ones where at least 60% of overlapping time agrees. [overlap ratio](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/apps/desktop/src/stt/useRunBatch.ts#L103), [remap](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/apps/desktop/src/stt/useRunBatch.ts#L405-L431).

### 2.5 Anarlog: the voiceprint crate and plugin

The design is conservative by construction and every threshold is in source.

- Span selection (`crates/voiceprint`): merge same-speaker words with gaps up to 400 ms into runs, cut out any portion where another speaker overlaps on the same channel, keep spans of 1.5 s to 10 s (long spans keep their middle), at most three per speaker. [SpanConfig](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/voiceprint/src/lib.rs#L36-L52), [select_speaker_spans](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/voiceprint/src/lib.rs#L62-L105).
- Embedding model: the same WeSpeaker ONNX as the diarizer, versioned as `wespeaker-embedding-onnx-1`; exemplars from a different model version are ignored at match time. [constants](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/plugins/transcription/src/voiceprint.rs#L13-L23), [version check](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/plugins/transcription/src/voiceprint.rs#L942-L946).
- Storage: vectors go into the OS keyring; SQLite holds metadata only, `sync_scope = 'local_only'`. Candidates expire after 45 days unless promoted to exemplars. [candidates migration](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/db-app/migrations/20260811090000_voiceprint_candidates.sql), [exemplars migration](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/db-app/migrations/20260802120000_voiceprint_exemplars.sql), [TTL](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/plugins/transcription/src/voiceprint.rs#L15).
- Capture domain: exemplars record whether they came from the direct mic, system audio, or mixed capture, and matching only compares within the same domain. [same-domain matching](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/voiceprint/src/matching.rs#L189-L213)
- Matching: cosine similarity, a speaker is named only when its best person scores at least 0.62, beats the runner-up by at least 0.08, and that person's best speaker is the same speaker with the same margin. Two speakers wanting the same person yields nothing. [thresholds](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/voiceprint/src/matching.rs#L3-L4), [mutual unique](https://github.com/fastrepl/anarlog/blob/e4379fb6ec48c1094374054faa97912de6b714a4/crates/voiceprint/src/matching.rs#L41-L105).

## 3. Implications for MacParakeet

Anarlog's advantage is not the model. Every lesson below is engine-agnostic and sits around FluidAudio's community-1 output, which is already the newer recipe.

1. **Pass the participant count and the channel shift into the clustering bounds.** `DiarizationService` already accepts an exact or range constraint, but the meeting finalizer diarizes the system channel with no count. Anarlog's rule is simple: if the session knows N participants, the system channel gets N minus one, a 1:1 call skips diarization, and an unknown count stays unconstrained. FluidAudio's `OfflineDiarizerConfig.withSpeakers` takes exactly these bounds. This is the cheapest change with the largest expected effect on over-splitting, the failure both Anarlog PRs name as the most common local one.

2. **Detect in-person meetings and diarize the microphone.** MacParakeet renders every mic word as the user, which is wrong whenever a laptop sits on a table. Anarlog's `in_person_capture` test (expected at least two participants, system channel carried at most 3 s of speech) is a two-line heuristic, and its follow-through is to diarize the mic channel with the full count and relabel to a mixed-capture channel only when at least two speakers actually emerge. ADR-028's retained raw microphone source makes this cleaner for MacParakeet than for Anarlog.

3. **Add an embedding-based consolidation post-pass over FluidAudio's labels.** `consolidate.rs` is independent of the diarizer: embed each label's clean spans (400 ms merge gap, no overlap, 1.5 s to 10 s, three spans per speaker), then merge labels that exceed the expected cap or match the same known voice. FluidAudio exposes the WeSpeaker embedding it already uses, so this needs no new model. It directly targets the "results are not the best" complaint if the complaint is fragmentation rather than confusion, which the owner should confirm on real recordings first.

4. **Make every manual correction an enrollment, with conservative matching.** Anarlog's voiceprint store is what the voiceprints research (Phase 0b) was heading toward, and its numbers are concrete: same-capture-domain matching, a 0.62 floor with a 0.08 margin, mutual uniqueness, elimination only when counts match exactly, 45-day expiry for unnamed candidates, vectors in the keychain, and owner self-enrollment when headphones isolate the mic. Adopting the thresholds blindly would be a mistake, since they were tuned on WeSpeaker ResNet34 embeddings and MacParakeet's FluidAudio embedding may differ, but the policy shape transfers.

5. **Keep speaker labels as an overlay with fixed precedence.** Anarlog never mutates provider output; provider index, automatic assignment, and user assignment are separate hint layers, re-diarization remaps user assignments by a 60% overlap rule, and "apply to all" is the default scope. MacParakeet's `DiarizationSegmentRecord` and speaker table can carry the same precedence without a schema rewrite, and it makes the consolidation and voiceprint passes safe to re-run.

Things not to copy: the post-stop gating that leaves most default users with channel labels only; the Soniqo path's synthetic word timings; and the assumption that the direct mic is always the owner without an echo check.

## 4. Failure scenarios and uncertainty

- **The reviewed revision is `main`, four days after the diarizer landed.** Which PRs are in the shipped `desktop_v1.4.21` build was not verified. Behavior described here may not match what an Anarlog user runs today.
- **Benchmark numbers are agreement with pyannote.ai `precision-2` on two clips**, not DER against human references, and the repo contains no AMI or VoxConverse results. The eval harness exists and the PROGRAM.md loop is defined, but no `results.tsv` is committed. Treat "1.8% to 4.7%" as a smoke test.
- **The bundled ONNX weights are unattributed in the tree.** I inferred segmentation-3.0 and WeSpeaker from code comments and docs, not from a model card or hash. Licensing of the embedding file (CC-BY-4.0 upstream) is a possible gap for Anarlog and would be one for MacParakeet if it copied the files.
- **Community-1 through Soniqo requires an exact count and ten minutes per channel**, so on typical meetings the older 3.1-style Rust pipeline is what actually runs. Its clustering threshold (0.7045) and 12 s minimum cluster are pyannote 3.1 defaults transposed, not tuned on Anarlog's own data.
- **Default-user reality**: the live transcript never has speakers, and post-stop diarization requires at least two other participants on the session plus a 632 MB model download. A user who records without a calendar event or participant list gets "You" and "Speaker 1" permanently unless they re-transcribe by hand. Anarlog's PR 7244 acknowledges extending the live repass to whisper and Argmax as a follow-up.
- **In-person detection can misfire**: a call where the far end stayed silent for the whole meeting is classified as in-person and the mic is diarized with the full count; the code comment accepts this.
- **Voiceprint matching depends on the calendar**: naming runs only when the participant list has at least two remotes, and elimination trusts that list exactly. Meetings with uninvited guests get no automatic names, by design.
- **Muesli's `DiarizerManager` versus `OfflineDiarizerManager`**: I read the type name and the telemetry `model_set: pyannote_streaming`, not FluidAudio 0.15.5 internals, so the exact model set Muesli runs is inferred.
- **Minutes' channel handling was not traced**, and OpenWhispr's live identifier was read for thresholds, not for its end-to-end accuracy.
- **MacParakeet's own line references** point at the working tree on 2026-09-06 with unrelated uncommitted edits; the linked `main` permalinks may drift.
