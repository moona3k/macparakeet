# Open-source patterns: scoped retrieval, agents, and RLM

Date: 2026-09-25. Research for MacParakeet's proposed multi-meeting Ask workspace; no implementation commitment.

## Recommendation

Use a model-independent domain layer and a small, capability-aware agent loop. Borrow scoped retrieval and explicit evidence records from document-chat systems; evaluate a code REPL separately. Supporting several providers does not establish equivalent tool reliability, context capacity, cancellation behavior, or answer quality across their models.

This report inspected current upstream source at the commits below. These are static source observations, not runtime verification, security audits, latency measurements, or proof of shipping releases. No upstream application was installed or executed. Only public GitHub metadata and selected source files were downloaded; private meeting data was not accessed.

## Onyx: scope must survive every search

**Observed.** `SearchTool` receives application-owned filters independently of model-generated queries. Its explicit-empty-source guard returns no documents when `source_type=[]`; `None` means unrestricted by that filter. The guard excludes project mode because that path intentionally ignores these user filters. The tool constructs user ACL filters, validates access to requested document sets, and bounds model-inferred source choices by the user's source restriction. This distinction has a dedicated test file. [Search tool](https://github.com/onyx-dot-app/onyx/blob/42650cd914cb7c378a9f2d91b7b1d7a6ceb6421f/backend/onyx/tools/tool_implementations/search/search_tool.py), [empty-selection tests](https://github.com/onyx-dot-app/onyx/blob/42650cd914cb7c378a9f2d91b7b1d7a6ceb6421f/backend/tests/unit/onyx/tools/test_search_tool_empty_source_selection.py).

The search pipeline builds `IndexFilters` combining document sets, source type, date ranges, tags, ACLs, tenant, project/persona identity, and attached-document IDs. A persona time floor cannot be loosened by a caller's date filter. A separately named forced-document-set setting applies to Search UI callers only and is off by default for chat; it must not be cited as proof of universal chat enforcement. Adjacent chunks from the same document are merged into evidence sections. [Pipeline](https://github.com/onyx-dot-app/onyx/blob/42650cd914cb7c378a9f2d91b7b1d7a6ceb6421f/backend/onyx/context/search/pipeline.py).

Citation processing receives a mapping from citation numbers to retrieved `SearchDoc` objects, accepts additional mappings as tools run, and tracks cited document identities while rendering streamed citations. This establishes source identity, not semantic proof that each cited passage entails its associated claim. [Citation processor](https://github.com/onyx-dot-app/onyx/blob/42650cd914cb7c378a9f2d91b7b1d7a6ceb6421f/backend/onyx/chat/citation_processor.py).

The chat loop runs a bounded number of model cycles, accounts for tool tokens, truncates history to budget, and removes orphaned tool responses. Its `LLM` abstraction separates invocation/streaming, tools, structured responses, model configuration, and timeout policy; the factory constructs a LiteLLM-backed adapter. No general code execution is necessary to get this repeated model/tool behavior. [Loop](https://github.com/onyx-dot-app/onyx/blob/42650cd914cb7c378a9f2d91b7b1d7a6ceb6421f/backend/onyx/chat/llm_loop.py), [LLM interface](https://github.com/onyx-dot-app/onyx/blob/42650cd914cb7c378a9f2d91b7b1d7a6ceb6421f/backend/onyx/llm/interfaces.py), [factory](https://github.com/onyx-dot-app/onyx/blob/42650cd914cb7c378a9f2d91b7b1d7a6ceb6421f/backend/onyx/llm/factory.py).

**Borrow.** Freeze selected meeting IDs and transcript revisions in a request-owned scope. Every search, passage read, summary read, and follow-up must take that scope from the application. Define empty selection deliberately. Keep citation handles in application-owned records, and expand adjacent passages when interpretation needs surrounding conversation.

**Do not infer or copy wholesale.** Onyx's filters represent a large server product with enterprise connectors and multiple modes. They are not proof that arbitrary per-meeting selection is enforced across all its paths. MacParakeet needs a simpler scope contract with no mode-specific escape from the user's selected meetings. No Onyx UI behavior or full index implementation was exercised here.

## AnythingLLM: a useful workspace and capability reference

**Observed.** Its standard streaming chat path assembles pinned document content and uploaded context, then searches the vector namespace identified by `workspace.slug`. Pinned documents are excluded from duplicated search context. Query mode can return an explicit no-context response. The inspected LanceDB provider opens that namespace's table and returns text alongside source metadata and similarity scores. This is concrete workspace scoping; it is not evidence of a per-turn checkbox subset inside that workspace. [Chat stream](https://github.com/Mintplex-Labs/anything-llm/blob/1f20188bd3c2c6e44bc132cc4a0777b1bf23708a/server/utils/chats/stream.js), [LanceDB retrieval](https://github.com/Mintplex-Labs/anything-llm/blob/1f20188bd3c2c6e44bc132cc4a0777b1bf23708a/server/utils/vectorDbProviders/lance/index.js).

Agent tools go beyond this initial retrieval. `memory.search` searches the invocation workspace, adds returned sources to the citation buffer, and returns passages to the model. Its no-result response suggests web search, and the same plugin can store new memory. Those are upstream product choices, not suitable defaults for a strictly curated, read-only meeting question. [Memory plugin](https://github.com/Mintplex-Labs/anything-llm/blob/1f20188bd3c2c6e44bc132cc4a0777b1bf23708a/server/utils/agents/aibitat/plugins/memory.js).

The document summarizer lists documents using the invocation's workspace ID, resolves a requested filename against that list, loads the document, and registers a citation. It returns full text if it fits the model context; otherwise its helper walks token-bounded sections and accumulates key points with cancellation support. This offers both targeted retrieval and a broader document-reading operation. Filename matching alone would be unsuitable for repeated meetings with identical names: MacParakeet should expose stable IDs with dates. [Document summarizer](https://github.com/Mintplex-Labs/anything-llm/blob/1f20188bd3c2c6e44bc132cc4a0777b1bf23708a/server/utils/agents/aibitat/plugins/summarize.js), [long-document helper](https://github.com/Mintplex-Labs/anything-llm/blob/1f20188bd3c2c6e44bc132cc4a0777b1bf23708a/server/utils/agents/aibitat/utils/summarize.js).

The AIbitat harness owns round/tool limits, provider selection, a citation buffer, and an abort controller. It checks abort state after streaming so a truncated tool call is not executed, and invokes the model again after tool results. Providers can use streaming or non-streaming execution. The Ollama adapter checks the model's native-tool capability and otherwise uses an `UnTooled` fallback; it also translates internal function history into provider-specific tool messages. This is strong evidence that model independence requires adapters and capability handling, not just a configurable model name. It does not prove fallback reliability on arbitrary local models. [Harness](https://github.com/Mintplex-Labs/anything-llm/blob/1f20188bd3c2c6e44bc132cc4a0777b1bf23708a/server/utils/agents/aibitat/index.js), [Ollama adapter](https://github.com/Mintplex-Labs/anything-llm/blob/1f20188bd3c2c6e44bc132cc4a0777b1bf23708a/server/utils/agents/aibitat/providers/ollama.js).

**Borrow.** Offer passage search plus bounded full-transcript reading, explicit progress, cancellation, and per-model capability checks. Preserve evidence metadata separately from text. Distinguish corpus coverage from a list of retrieved citations: finding four relevant chunks does not establish that all selected meetings were reviewed.

**Defer.** Its broad tool catalog, automatic web fallback, writable memory, and multiple agent channels exceed the initial meeting research job. Do not adopt them simply because the infrastructure provides them. The report does not claim document removal purges old conversation context; that lifecycle was not audited.

## RLM: genuine programmable context, with a separate execution boundary

**Observed.** `RLM.completion` places input in an environment and drives a repeated model/code loop. The implementation exposes recursion depth, iteration limits, timeout and optional cost budget, optional compaction, and persistent environments across turns. At the inspected revision, configuration supports only one additional backend for recursive subcalls. The root and subcall clients are distinct choices. [RLM implementation](https://github.com/alexzhang13/rlm/blob/d04208afbad29ca675ab13478c40ee8bebc84bfe/rlm/core/rlm.py).

`BaseLM` supplies synchronous/asynchronous completion and usage interfaces. Its concrete client factory supports OpenAI, Anthropic, Gemini, Azure OpenAI, and several gateways, plus a vLLM mode requiring a local server URL. Thus the research implementation is provider-pluggable, although its abstraction and code-generation workload differ from a native structured-tool chat loop. A stale factory docstring lists only OpenAI; executable branches establish the broader support. [Base client](https://github.com/alexzhang13/rlm/blob/d04208afbad29ca675ab13478c40ee8bebc84bfe/rlm/clients/base_lm.py), [factory](https://github.com/alexzhang13/rlm/blob/d04208afbad29ca675ab13478c40ee8bebc84bfe/rlm/clients/__init__.py).

The local environment exposes corpus variables such as `context_0`, model-query helpers, and Python execution with persistent globals/locals. Its allowed builtins include `open` and `__import__`. Despite comments calling its namespace sandboxed, this is not an operating-system confinement boundary. Docker and remote environment implementations are separate options; their existence does not establish isolation suitability for a signed Mac app. [Local REPL](https://github.com/alexzhang13/rlm/blob/d04208afbad29ca675ab13478c40ee8bebc84bfe/rlm/environments/local_repl.py), [Docker environment](https://github.com/alexzhang13/rlm/blob/d04208afbad29ca675ab13478c40ee8bebc84bfe/rlm/environments/docker_repl.py).

**Borrow experimentally.** A corpus outside the root model prompt, selective inspection, bounded subquestions, and explicit usage accounting could help exhaustive comparisons over many meetings. A benchmark should compare these against the simpler tool loop on the same corpus and models.

**Do not adopt by default.** This library does not supply MacParakeet's meeting picker, transcript revision semantics, citation contract, or selected-source lifecycle. Persistent Python variables can retain removed material. Timeout checks between iterations are not proof that arbitrary generated code can be forcibly interrupted. Cost bounds depend on backend accounting. Any experiment needs a separate process/execution policy and application-owned evidence handles; Python strings alone are insufficient provenance.

## What model-agnostic should mean for MacParakeet

The proposed contract should keep selected source IDs/revisions, evidence handles, conversation state, tool schemas, run budgets, and cancellation outside provider-specific messages. An adapter translates normalized model events into text deltas, complete tool calls, usage, completion, and errors. The application validates tool names/arguments and source scope before execution.

Expose model capabilities rather than promising uniform behavior: native tools, structured output, usable context budget, streaming, cancellation, usage availability, and any approved subcall model. Qualify named model/provider combinations with real questions. Where a model cannot reliably use tools, offer an explicit constrained retrieval-and-answer mode or mark agent mode unsupported; do not silently claim equivalent agent capability.

Evaluate late-meeting evidence, conflicting decisions across dates, identical recurring titles, exhaustive action-item extraction, empty selections, removal of a previously cited source, cancellation during reads, and local-only operation. Measure supported claims, coverage, wrong-source access, latency, tokens, and cancellation behavior. No measured comparison among these projects was performed in this research.
