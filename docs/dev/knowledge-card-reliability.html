The reviewed stable-build telemetry recorded 696 failures among 1,677 knowledge-card LLM-stage outcomes. This repair addresses specific request and recovery defects without changing capture or generic formatter behavior.

What the numbers mean. LLM success happens before citation resolution and the database save. It is not a saved-card counter. A process session is not a person.

One bounded recovery request

Previously, embedded-schema failures repeated identical input and a 700-token request. Native-schema failures had no retry. Finish reasons were ignored.

Now, an explicit output-limit finish permits one fresh, shorter response with more output room. Malformed or empty-synopsis JSON gets one corrective prompt. Partial model text is never replayed as instructions or saved. Cloud and other unknown-window routes keep the successful 700-token initial allowance and permit 4,096 only after explicit truncation, including manually named models and overridden endpoints. Native Ollama uses 2,048/4,096; LM Studio uses 1,024/1,536. Custom OpenAI-compatible endpoints use 700/2,048. Capped cloud responses may need an extra round trip.

Ollama previously ignored the raw card token setting. The card caller now uses the existing option resolver and reserves input inside the adapter's real 8,192-token window. Generic requests retain their prior behavior.

Waiting is different from regenerating

A configuration lock is local contention before a provider call. Four reads at most, separated by cancellable 100/300/600 ms waits, allow a short settings update to finish. No settings are written and no model request is made while setup remains blocked.

The safety boundary stays in the database

After model latency, the generator checks the transcript, speaker attribution and correction revision. The repository repeats freshness checks in the save transaction. A stale, deleted, malformed or cancelled result cannot replace a valid card or recreate deleted source data.

Verification and remaining gates

Regression fixtures exercise real HTTP adapters, a real configuration file lock and in-memory repositories. Consult the PR for exact-head review and CI evidence; local syntax parsing is not a build or test result.

The related Ollama/Gemma report needs an actual-model synthetic canary. This machine has no installed Ollama model. No claim of production improvement or resolution of every historical failure is made. Post-release comparison must use exact-build, comparable cohorts.
