What stays—and why.

Keep all five

We’re removing an extra floating label and a false silence warning—not rolling back useful state handling. Each item below links to its visual example. These behaviors already exist and remain intentionally unchanged.

02 · During capture startup

Honest status + a way to stop

“Starting…” stays inside the capture tile, panel and Meetings status. Stop remains available. No active recording timer, pause or mute until capture is accepted. This avoids claiming audio is recording before it really is.
04 · Only when a prompt fails

A small, actionable error

Caption-sized red text stays beneath the transcript title. If the transcript or AI context changes during preparation, reject the stale request and explain how to retry. No new toast or floating warning.
05 · While context is preparing

Generate / Regenerate guards

The existing buttons temporarily disable during preparation. This prevents overlapping actions from using unfinished or obsolete context. The guard adds no new progress panel or “Preparing…” label.
06 · Only when setup fails

Recovery advice that fits the cause

The existing “Try this:”, Retry and Open Settings controls remain. Network, disk-space and model-availability failures get appropriate guidance instead of a generic dead end. No extra onboarding step.
07 · After a rename

One saved title, everywhere

Transcript, Library and Recent Meetings reflect the persisted name. A failed save must not look successful; stale list loads must not restore the old title. Same rename UI, reliable saved state.

Genuine audio failures still matter. Interruptions, unavailable sources, missing coverage, capture failures and degraded playback fallback remain partial and retain warnings. A fully captured quiet track is valid recording content; its signal diagnostics stay internal. Long-transcript loading improvements and internal timing diagnostics are also untouched.

—

What wasn’t added

Large source diffs do not necessarily mean more UI
  • No new main tabs, onboarding steps, or onboarding recovery buttons in this PR.
  • No new Library rename/delete/export dialogs. The large view diff was predominantly decomposition and formatting.
  • Long-transcript lazy-row work adds no screen or control. It changes loading granularity; visual layout is intended to remain equivalent. No performance benchmark is claimed here.
  • The meeting queue’s new timing diagnostics are internal logs. They are not additional on-screen stages.
  • Rare stop/processing failures gained explicit cancellation or automatic-retry wording. That feeds existing error presentation; it is not a new normal-path status surface.
